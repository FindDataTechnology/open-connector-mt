# 淘宝 / 京东平台直连骨架契约（实现挂起）

状态：**骨架先行，实现挂起**。目录 1570 家 provider 内无淘宝/天猫/京东
（ADR 0002 复核记录），ERP 侧以角色绑定声明，实现按锚点客户逐个上线。
国内首要通道是**商家电商 ERP**（`merchant-erp-skeleton-contract.md`，一条通道给三腿）；
平台直连是第二顺位，用于没有 ERP 或客户明确要求直连的场景。

拼多多**不在本契约内**：上游接口 schema 缺失，ERP 侧连绑定都不声明，目录也不留槽位。

## 载体

- 一平台一 provider：`src/providers/taobao/`、`src/providers/jd/`；
- 端点代码字面量（淘宝 TOP 网关 / 京东开放平台网关），禁止从凭证取 base URL；
- 天猫与淘宝共用同一 provider（同一 TOP 网关、同一套授权），以店铺类型区分，不复制目录条目。

## 凭证形态

| 平台 | 授权 | 说明 |
|---|---|---|
| 淘宝/天猫 | OAuth（TOP 网关 + session key） | 商家授权后拿 session key；过期为常态，需 refresh 并在失败时返回 `AUTH_FAILED` |
| 京东 | app key + app secret + 签名 | 每次请求签名；签名材料只在 provider 内 |

频控：两家都按应用级 QPS 限流，超限返回业务错误码（不一定 429），provider 需映射为
`RATE_LIMITED`，避免被读成「无数据」。

## 动作面骨架（全部 `operationType=read`）

1. `list_orders`：按店铺 + 时间窗（订单号、支付时间、金额、状态、退款标记），游标分页 + 按修改时间增量；
2. `list_settlements`：账单/结算（账期、应结、扣费、实结）——**独立于订单面**；
3. `list_inventory`：SKU 维可用/锁定/在途；
4. `get_shop`：店铺 id、卖家昵称、币种、账期口径。

## 验收判据（一轮闭环）

1. 某账期账单合计 = 订单合计 − 扣费 − 退款 + 补贴，差额为零或可逐项归因；
2. 同一修改时间窗重复拉取幂等；翻页读完才算全量；
3. 授权过期返回 `AUTH_FAILED`（而不是空列表），由客户侧重新授权后自动恢复。

## 矩阵与对外口径

- 实现前：`taobao.*` / `tmall.*` / `jd.*` 保持 `unmapped`，原因「骨架待锚点客户」，
  对外统一说**「需一次接入」而不是「不支持」**；
- 实现并真实读取后才升 `available`；
- 拼多多：`unavailable`，原因「上游接口 schema 缺失」，对外说「不提供」，不给日期。
