# add-welcome-entry

## Why

`TENANCY=oidc` 下连接器域没有面向客户的欢迎面，客户从任何入口进来都会失去产品上下文：

1. **根路径是死路**：`connector.finddatatech.cloud/` 落到管理台代码路径，对所有人（含已登录租户）呈现「管理员 token 解锁墙」——官网介绍页的「在线体验」按钮与壹座应用中心的「萬星·连接器」卡片都指向它，客户第一眼看到的是英文的管理员口令输入框。
2. **`/me` 未登录卡信息不足**：现有引导卡只有品牌 + 一句说明 + 登录按钮，用户读完仍不知道「这是什么产品、令牌给谁用、下一步做什么」。

客户旅程应为：任一入口 → 欢迎卡（知道这是什么、三步怎么做、去哪看详情）→ 登录 → 「我的连接」面板。

## What Changes

- **根路径导流**：`TENANCY=oidc` 下 console 根路径 `/` 导流到 `/me`（欢迎卡 / 用户面板）；管理台路由（`/overview` 等）保持既有 admin token 解锁规则；`TENANCY=off` 下行为逐字节不变。
- **未登录欢迎卡加厚**（`/me`）：品牌 + 一句话产品定位（与官网产品介绍页同源口径：1500+ 服务、万级预置动作、统一凭据托管）+ 三步行（① 统一身份登录 ② 添加你的 SaaS 连接 ③ 铸造访问令牌并粘贴到壹座）+ 「了解产品」链接（新标签 → 官网产品介绍页，按界面语言选中文/英文页）+ 一行安全承诺；登录按钮维持唯一登录入口。
- **六语言**：新增文案键在 en / zh-CN / zh-TW / ja / ru / fr 全配（i18n parity 测试自动兜底）。
- 已登录面板不变（PAT 卡置顶与既有接入指引已覆盖登录后场景）。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `tenant-console`：「未登录引导页」要求加厚（定位句 + 三步行 + 了解产品链接 + 安全承诺）；新增「根路径导流到用户面板」要求（`TENANCY=oidc` 下 `/` 导流 `/me`，管理台路由与 off 档不变）。

## Non-goals

- 不动 `TENANCY=off`（上游管理台）的任何行为——根路径导流与欢迎卡均显式限定 `TENANCY=oidc`。
- 不改 OIDC 登录链与跨域铸牌（`cross-mint`）的既有行为；壹座侧弹窗行为保持不变（paas `add-connector-context` 只加点击前的上下文）。
- 不改 `/me` 已登录面板的信息架构（PAT 卡置顶、连接分组、运行记录卡均不动）。
- 管理台解锁面本身不删——保留在 `/overview` 等路由，管理员经直连 URL 进入。
- 不做根路径落地页（独立于 `/me` 的第二匿名面）；不做截图/图示引导。

## Impact

- 前端：`web/src/ui.tsx`（fork 已改，根路径导流落点）、`web/src/user/user-page.tsx`（fork 专有，欢迎卡加厚）、`web/src/locales/*.json` 六语言新键。
- 服务端：仅在所选导流实现需要时触碰（design 定案；若走 console 壳层则无服务端改动）。
- 无 API / DB / 迁移变化；`src/providers/**` 不动。
- 上游可合并性：改动集中 fork 追加区域，fork delta 增量薄；`TENANCY=off` 行为不变。
- 官网介绍页 demoUrl（connector 根路径）无需改动——导流后 302 透明直达欢迎卡。
- 验收：vitest 组件/壳层测试（欢迎卡内容、根路径导流、off 档不变）+ 既有 i18n 键完整性测试 + 线上实机（浏览器匿名/已登录两态走一遍）。
